# 素材成章与智能排序设计（2026-09-18）

> 状态：已与产品确认（对话拍板）  
> 适用范围：`refind-demo` 灵感卡片 → 全屏笔记编辑；`generate-note` 按章节结构生成  
> 前置：素材右栏、多选整理、`generate-note` Edge 已落地  
> 非目标：生产上线、脑图、按来源/时间「粗排」作为成章手段

## 1. 问题

用户用多张灵感卡片写一篇笔记时：

1. 收藏顺序往往是乱序，对「串成有条理的文章」没有帮助  
2. 仅靠上移/下移调整 20 张卡成本过高  
3. 按来源 / 知识库 / 收藏时间一键粗排**无效**——顺序的意义是**叙事顺序**，服务「生成笔记」

结论：成章应由 AI 基于卡片内容完成；面板展示并允许微调章节结构；生成严格按该结构写作。

## 2. 目标

1. 进入带素材的全屏笔记编辑时，若尚无章节结构且素材 ≥ 2，**自动成章**  
2. 右侧素材面板以 **章节标题 + 章下挂卡** 展示；支持拖卡换章、章内排序、改章名  
3. 「生成笔记」按 **章节顺序 → 章内卡顺序**（+「我的想法」）生成  
4. 「重试成章」在已有正文时走确认流（仅更新结构 / 更新并重新生成）

## 3. 非目标

- 用元数据（来源 / 时间）替代语义成章  
- 强制用户在进编辑前单独走「整理台」页（本版成章发生在进入编辑时）  
- 改动 RAG 主链路  
- 资料编辑 fan-in 等同步边角（已有 sync-note 范围外）

## 4. 信息架构

| 表面 | 职责 |
| --- | --- |
| 灵感页多选 +「整理为笔记」 | 选材；一次带入多卡（已有） |
| 进入全屏编辑 | 触发自动成章（条件见 §5） |
| 右侧素材面板 | 展示/微调章节与挂卡；展开全文；「我的想法」；加卡/删卡 |
| 「生成笔记」 | 按当前章节结构写正文 |
| 「重试成章」 | 重新跑成章；有正文时二次确认 |

收藏时间顺序**不再**作为生成的硬约束。

## 5. 自动成章（进入编辑）

**触发条件（同时满足）：**

- 全屏灵感编辑，且 `showMaterials` / 已有绑定素材  
- 绑定卡片数 ≥ 2  
- 笔记尚无已保存的章节结构（见 §8）

**行为：**

1. 面板进入短暂「成章中」态（可继续看扁平占位或 skeleton，不挡返回）  
2. 调用成章服务（Edge，建议 `outline-note-materials` 或扩展 `generate-note` 的 `mode=outline`）  
3. 成功 → 写入章节结构并刷新面板  
4. 失败 / 超时 → 扁平列表展示 + 「重试成章」入口；不阻断写作与手动加卡

**卡片数 = 0 / 1：** 不成章；0 无面板内容；1 张可单列无章或单章「素材」。

## 6. 面板交互

### 6.1 展示

- 3～5 个章节（模型可少于 3、多于 5 时前端可折叠或提示，默认接受 2～6）  
- 章标题可内联编辑  
- 章下卡片：序号（章内）、来源、摘录、展开全文、「我的想法」、移除  
- 支持面板收起 / 右侧 FAB（沿用现交互）

### 6.2 拖拽

- 章内排序  
- 跨章拖动  
- 允许暂时空章；**生成时跳过无卡章节**（不弹窗打断）

### 6.3 加卡 / 删卡

- **添加灵感卡片**（多选弹窗，已有）：新卡进入「未归章」区；用户可拖入某章，或点「重试成章」整包重排  
- **删卡**：仅移出素材；**已生成正文不回改**（既有规则）

### 6.4 重试成章

| 笔记状态 | 行为 |
| --- | --- |
| 尚无生成正文（无可用 sections / 用户未成功生成过） | 静默更新章节结构，不弹窗 |
| 已有生成正文 | 先更新面板结构，再弹窗：「结构已更新，是否用新结构重新生成正文？」→ **仅更新结构** / **更新并重新生成** |

「更新并重新生成」走现有生成中禁编、`note_revisions` before_generate、成功滚至文首等逻辑。

### 6.5 生成中

面板只读：不可拖、不可改章名、不可加删卡（与生成中禁编一致）。

## 7. 生成笔记（与成章的关系）

输入给模型：

1. 有序章节标题列表  
2. 每章下有序卡片：`content_snapshot`、`question_snapshot`、`answer_mode`、引用快照、「我的想法」  

输出仍为 `notes.content` 的 `sections`（可含章标题对应段落 + 卡引用），并保持 `[n]` 回链卡片能力。

**无章节结构时（兜底）：** 按当前扁平素材顺序生成（兼容旧笔记）；文案可提示「建议先成章」。

## 8. 数据模型（建议）

在笔记上持久化大纲，例如 `notes.content.outline` 或并列字段（实现计划选定其一）：

```ts
type MaterialOutline = {
  version: 1;
  chapters: Array<{
    id: string;
    title: string;
    cardIds: string[]; // 有序；须属于 note 绑定素材
  }>;
  unassignedCardIds?: string[]; // 「未归章」
  updatedAt?: string;
};
```

约束：

- `cardIds` 并集应覆盖当前绑定素材；删卡时从 outline 移除  
- 加卡默认进 `unassignedCardIds`  
- 打开笔记时若 outline 与绑定卡不一致，做一次 reconcile（丢掉无效 id，缺的进未归章）

## 9. API（建议）

`POST outline-note-materials`（名称以实现为准）

- Body: `{ noteId }` 或 `{ cardIds, thoughtsByCardId }`  
- 鉴权与归属同 `generate-note`  
- 返回：`MaterialOutline`  
- 不写正文、不写 `note_revisions`（成章 ≠ 生成）

「更新并重新生成」= 成章 API + 现有 `generate-note`（generate 需读取 outline）。

## 10. 验收

- [ ] ≥2 卡首次进入全屏 → 自动成章 → 面板为章节挂卡  
- [ ] 拖卡换章 / 章内排序后生成，正文结构与面板一致  
- [ ] 无正文时「重试成章」不弹窗；有正文时弹窗且「仅更新结构」不改正文  
- [ ] 「更新并重新生成」会改正文并留 revision  
- [ ] 新卡进未归章；删卡不改已有正文  
- [ ] 成章失败可重试且不挡编辑  
- [ ] 生成中面板只读  

## 11. 风险

| 风险 | 缓解 |
| --- | --- |
| 进编辑等待成章过久 | 超时扁平兜底 + 重试；可后台完成后热更新面板 |
| 成章与用户意图不符 | 可改章名、拖卡、重试成章 |
| 旧笔记无 outline | 生成走扁平顺序；下次进编辑可自动成章 |
| 模型章数不稳 | prompt 约束 3～5；前端接受 2～6 |
