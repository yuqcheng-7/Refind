# AI 回答可读性与行内引用浮卡设计

> 日期：2026-09-15  
> 最近修订：2026-09-17（结构层级 / 编号修复 / 短标题标准）  
> 状态：**已落地**（用户选 A：浮卡；回答结构与短标题标准已产品确认）  
> 范围：首页 + 知识库 AI 回答渲染（`AnswerContent` + `formatAnswerText` + RAG/general prompt）  
> 关联：`2026-09-17-llm-query-rewrite-design.md`（追问检索）；下一阶段为笔记模块智能化

## 目标

1. 回答按分段/列表/加粗可读展示，避免「一整坨」。
2. `[n]` 作为行内可点角标，跟在对应句/段后。
3. 点击弹出浮卡：资料标题、摘录、「查看资料」。
4. 去掉回答底部引用芯片堆。
5. **层级清晰**：大标题 / 有序小分点 / 无序并列点可读；并行项不得全部显示为「1.」。
6. **短标题加粗**：仅「先命名再展开」的短标签加粗，非整句硬拆标题。

## 非目标

- 完整 Markdown 引擎 / 数学公式（表格、任务列表、嵌套引用等）
- 历史会话持久化列表（另见会话历史分面设计）
- 改动笔记编辑器引用（下一阶段笔记智能化再对齐同一 `[n]` 交互）

## 实现要点

### 渲染与清洗

- 共享 `AnswerContent`：规范化换行 + 轻量 Markdown 渲染（安全短 `**bold**`、`#` 标题、有序/无序列表、`一、` 大标题、`·` 并列点、`[n]`）
- **全局清洗：** `sanitizeRagAnswer`（前后端共用：`formatAnswerText.js` / `answerFormat.js`）先修结构，再只保留成对短加粗，**删除全部残余 `*`/`**`**，保证界面永不露出残星；截图级回归测试锁住
- 浮卡 dismissable；「查看资料」走已有预览 URL
- 服务端 `resolveRagAnswerOutcome` 走 `sanitizeRagAnswer`；普通聊天仍全量去 Markdown
- **浮卡定位：** portal 到 `document.body` + 高 `z-index`；相对触发角标定位并夹取视口；底部避开 sticky composer
- 不足回答固定文案「暂无相关资料」时不渲染引用角标

### 结构层级（产品确认 · 2026-09-17）

| 层级 | 标记 | 规则 |
| --- | --- | --- |
| 大标题 | `一、二、三、` | 约 12 字，单独成行；其下才能跟小分点；禁止小分点后再套「一、二、三、」 |
| 有序小分点 | `1. 2. 3. 4.` | 阿拉伯数字**必须递增**，数字后空格；禁止多个「1.」并列 |
| 无序并列 | `· ` | 无先后关系时使用 |
| 换行 | — | 禁止「一、标题1.」「……。二、标题」粘行 |

**前端修复（模型仍可能全写 `1.`）：**

- `rewriteParallelSectionTitles`：同簇并行标题全部以 `1.` 开头时，重编号为 `1. 2. 3. 4.`（**不**升格为「一、二、三、」）
- `demoteRestartedOrderedItems`：已有递增序列后再出现重启的 `1.` → 降为 `· `
- `splitAnswerBlocks`：有序项下的正文续行 / `·` 子点归属正确；CSS `ol` 不因 restart 全显示为 1.

### 短标题标准（产品确认 · 2026-09-17）

仅当一条分点需要先「命名」再展开时使用短标题：

| 约束 | 取值 |
| --- | --- |
| 长度 | **2～12** 字（名词/动宾；不含 `。！？`） |
| 格式 | `**短标题：**` 后接正文（正文不加粗） |
| 不要硬造 | 整句说明、举例、因果直接写正文；没有独立主题就不要拆标题 |
| 其它加粗 | 尽量少用；短标题以外若加粗，只包 2～8 字短词且必须成对；不要把「1. xxx」整行加粗 |

**前端识别：** `parseListItemLead` 识别 2～12 字短标题并渲染为加粗标签；超长当正文。

### Prompt 对齐

- RAG：`RAG_SYSTEM_RULES_BASE`（`ragRetrieve.js`）写入上述层级 + 短标题规则 + 句末 `[n]`
- General：同等结构约束（无知识库引用）
- 引用：句末 `[n]`；不要文档名、不要末尾参考列表
