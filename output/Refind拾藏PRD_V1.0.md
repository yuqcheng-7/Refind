# 一、项目概述

## 1.1 项目背景

在工作、学习和研究过程中，用户会在小红书、微信公众号、知乎、浏览器网页等渠道收藏案例、文章、教程和观点。

但当需要完成竞品分析、方案撰写、概念学习等具体任务时，用户往往不记得资料保存在哪里，也难以快速判断哪些历史收藏与当前问题相关，仍需花大量时间重新搜索、逐篇阅读和手动整理。

因此，用户的核心痛点并非“无法收藏”，而是：

> 已积累大量历史资料，却难以在需要时高效将其转化为解决具体任务的依据与思路。

## 1.2 项目目标

### 1.2.1 业务目标

面向高频收集外部信息，且需要在工作、学习或研究中持续调用资料的个人知识使用者，构建以“个人知识高效调用”为核心的 AI 产品。

通过降低用户从资料收集、找回、理解到应用的时间成本，建立“随手沉淀资料、遇到问题优先调用个人知识库”的使用习惯，并为后续扩展账号同步、多模态资料导入、共享知识库等能力奠定基础。

### 1.2.2 产品目标

Refind 因此将分散收藏沉淀为个人知识库，并通过 AI 帮助用户提升资料使用效率。用户保存资料后，AI 自动提炼摘要与标签，帮助资料形成基础结构；当用户在工作、学习或研究中遇到具体问题时，可直接用自然语言向个人知识库提问。AI 从相关资料中检索内容，归纳为回答、分析思路或信息线索，并展示每个关键结论的来源，方便用户核验和继续使用。

用户不再只是“找回一篇收藏”，而是能够基于过去积累的资料，更快地理解问题、形成思路并推进当前任务。

为实现上述目标，产品能力围绕以下方向展开：

- **资料沉淀**：将分散收藏转化为可管理的个人知识资产；
- **知识组织与找回**：支持按主题管理资料，并快速定位相关内容；
- **AI 知识调用**：支持用户围绕具体问题，与个人知识库进行对话；
- **可信回答与核验**：确保 AI 回答有资料依据，用户可追溯、核验并继续使用。

### 1.2.3 产品定位

> Refind 是一款面向工作、学习与研究场景的 AI 个人知识助手。它帮助用户将日常收藏与文件资料沉淀为可管理、可检索、可对话的个人知识库；首页既可进行任务导向的通用 AI 对话，也可在用户选择知识库或标签后，切换为仅基于个人资料、可溯源的严格 RAG 回答。

# 二、用户与场景分析

## 2.1 目标用户

Refind 面向高频收集外部信息，并需要将资料用于实际工作、学习或研究任务的个人知识使用者。V1 优先覆盖以下两类用户：

| 用户类型 | 典型人群 | 资料类型与调用任务 |
| --- | --- | --- |
| 职场知识工作者 | 产品、运营、市场、咨询、设计等从业者 | 收藏行业文章、竞品案例、用户洞察、活动玩法与方法论；用于方案撰写、竞品分析、项目调研、内容策划或汇报准备。 |
| 研究与学习人群 | 学生、研究生、备考者及转行者 | 收藏课程资料、论文、教程、岗位信息、面试经验和学习方法；用于理解概念、梳理主题、准备考试、开展研究或解决学习问题。 |

两类用户的共同需求是：

> 当我面对一个具体问题时，我希望直接向自己积累的资料提问，获得有依据、可核验的回答与思路，而不是重新搜索和逐篇翻找。

## 2.2 用户痛点

| 用户阶段 | 用户行为 | 核心痛点 |
| --- | --- | --- |
| 信息发现 | 在社媒、网页或文章中发现有价值内容 | 资料来源分散，难以统一沉淀。 |
| 信息保存 | 使用平台收藏、复制链接或截图保存 | 缺少统一结构，后续难以回忆内容价值与适用场景。 |
| 资料管理 | 历史收藏不断累积 | 主题混杂，难以按任务或领域组织。 |
| 资料找回 | 围绕当前任务寻找过往资料 | 不记得标题、平台或关键词，翻找成本高。 |
| 知识理解 | 阅读多篇资料并判断其价值 | 需要手动通读、提炼、比较和归纳。 |
| 任务应用 | 将资料用于方案、调研或学习 | 难以快速形成有依据的答案与思路；通用 AI 回答又难以核验。 |

## 2.3 核心使用场景

### 场景一：工作调研与方案准备

用户需要完成竞品分析、活动方案、内容策划或项目调研，但无法快速找回过去收藏的案例与方法论。

> 根据我收藏的资料，会员活动可以从哪些维度设计？

Refind 从个人知识库中检索相关案例与方法论，输出可参考的分析维度、案例做法与思考方向，并附带对应资料来源。

### 场景二：学习与概念理解

用户学习某一主题时，已经收藏了教程、文章或论文，但需要理解概念关系或解决具体问题。

> 根据我收藏的 RAG 资料，召回和重排序分别解决什么问题？

Refind 基于相关资料进行归纳，说明概念关系与适用场景，并展示支撑回答的原文片段。

### 场景三：资料回顾与定位

用户只记得过去保存过某类资料，但无法记起准确标题或关键词。

> 提高新用户留存的方法

Refind 返回语义相关的资料，并展示标题、匹配片段、标签和所属知识库，帮助用户快速定位需要的内容。

## 2.4 核心用户流程

`发现资料 → 保存至知识库 → 自动结构化 → 在任务中搜索或提问 → 获得有来源的资料/回答 → 核验并继续使用`

# 四、详细功能需求

## 4.1 首页：知识库总览

登录后的首页为欢迎区 + 全局 AI；**知识库**为并列一级页（资料区 + 当前库 AI）。侧栏提供导航、常显知识库列表与搜索、账户入口。用户注册成功后系统自动创建默认知识库；进入知识库页时再选中并展示资料。首页 AI 无知识库或标签范围时为任务导向的通用对话，有范围时才切换为严格 RAG。

页面最终采用已确认视觉稿 `exec-9588f1f2-ccd1-4ef2-bc8c-57172aedfcb3.png` 所示的克制工具型视觉与紧凑列表信息密度（后续布局已确认为全宽工作台，见设计文档）。产品标识“Refind · 拾藏”使用衬线字体；知识库标题、正文、按钮和所有 UI 文案统一使用无衬线字体，避免在页面中混用多种标题字体。

| 区域 | 详细需求 |

## 4.2 创建知识库

| 字段/功能 | 规则 |
| --- | --- |
| 知识库名称 | 必填，1–30 字；同一用户下不可与已有知识库重名。 |
| 知识库简介 | 选填，最长 100 字。 |
| 知识库图标 | 创建时从系统预设图标中选择；用于左侧知识库列表识别，不影响资料搜索与 AI 检索。 |
| 创建按钮 | 名称合法时可点击。 |
| 取消按钮 | 关闭弹窗，不保存输入内容。 |

创建成功后，左侧新增并高亮当前知识库；右侧切换为该知识库的空资料列表，并展示“添加第一篇资料”引导。

## 4.3 添加资料

### 4.3.1 添加入口与支持类型

| 功能 | 规则 |
| --- | --- |
| 添加资料菜单 | 提供“粘贴链接”和“上传文件”。首页 AI 输入框不提供上传入口。 |
| 支持类型 | 链接、图片、PDF、DOC/DOCX、Markdown、TXT、PPTX、XLSX、CSV。 |
| 所属知识库 | 添加资料入口仅位于当前知识库；链接或文件确认后直接归属当前知识库，不在导入中选择归属。 |
| 批量处理 | 文件可多选，链接一次添加一条；每项独立入队、独立显示状态。 |

如需保存到其他主题，用户须先创建并切换到对应知识库后再添加资料；保存后仍可通过“移动资料”变更归属。

### 4.3.2 直接入库与解析中

链接完成校验或文件上传完成后，系统立即在当前知识库创建资料卡片，并放在资料列表底部；不经过预览、确认保存页面。按钮旁的白色进度浮窗按项目展示上传/解析队列，卡片在来源平台与标签位置显示“解析中”、圆形进度和百分比。成功后，卡片展示来源平台、摘要与标签，并参与搜索和 AI 问答。

链接提取正文；图片进行 OCR 与视觉描述；PDF、DOC/DOCX、Markdown、TXT 提取可读文本；PPTX、XLSX、CSV 提取可读的幻灯片或表格内容。全部成功资料均生成摘要、标签与检索切片。

### 4.3.3 解析失败与降级

解析失败时保留资料卡片，显示失败原因及“重新解析 / 删除”。同一资料连续三次失败后自动降级为仅链接或仅附件：保留原始链接/附件，且仍可无限次手动重新解析，但在成功前不参与搜索、RAG 或来源引用。


## 4.4 知识库资料列表

资料卡片采用紧凑的扁平列表卡片，包含网页/文件预览图、标题、一行截断摘要、`#标签`、创建时间及来源平台标签。来源平台标签以小圆点加平台名称呈现。解析中卡片固定在列表底部并显示进度；成功后自动入库的资料显示新增标记；用户点击该资料后，标记消失。

| 排序方式 | 规则 |
| --- | --- |
| 时间 | 从新到旧、从旧到新。默认从新到旧。 |
| 标题 | A–Z、Z–A。 |

资料列表额外提供来源平台单选筛选，选项为“全部来源、小红书、抖音、微信、知乎、B 站、其他”，默认“全部来源”；筛选菜单按“平台小圆点 + 平台名称”展示。来源筛选、资料关键词搜索与排序为 AND 关系：先限定当前知识库，再同时应用关键词匹配和来源条件，最后按所选排序规则输出。点击排序入口打开排序浮层；浮层按“时间”“标题”两组展示，每次仅选择一种排序规则，标题组默认 A–Z。待补充内容资料不参与搜索。

## 4.5 搜索建议浮层

| 状态 | 页面表现 |
| --- | --- |
| 输入为空 | 不展示浮层。 |
| 搜索中 | 展示加载状态。 |
| 有结果 | 展示资料列表。 |
| 无结果 | 展示“未找到相关资料”。 |
| 关闭 | 点击空白处或关闭按钮关闭浮层。 |

每条结果展示资料标题、所属知识库、匹配内容片段、标签和来源平台；点击条目跳转资料详情页。搜索采用关键词匹配，不调用 Embedding 或 RAG 检索。

## 4.6 资料详情页

展示标题、所属知识库、来源平台、保存时间、原始链接、AI 摘要、标签、正文或内容节选及资料状态。支持查看原文、编辑资料、移动资料、重新解析和删除资料；删除需二次确认，并删除关联片段与向量索引。资料可移动至任意知识库（包括默认知识库）。待补充内容资料需突出展示重新解析入口。

## 4.7 AI 对话页

AI 对话区固定在工作台右栏，提供新建会话按钮与仅图标的历史会话入口；会话列表按最近更新时间倒序展示。用户可新建、查看、继续、**内联重命名**或删除会话。

**会话分面（2026-09-15）：**

- 首页历史与知识库历史相互独立；不同知识库的会话列表也相互独立。
- 「新建 / 新增会话」立即创建标题为「新会话」的草稿并显示在对应历史列表；首条提问后标题改为问题摘要。
- 首页未选知识库的对话记入首页历史；首页仅选单个知识库提问时记入该知识库历史；知识库面板内提问始终记入当前库。

用户可输入自然语言问题，并通过一个或多个 #标签 聚焦资料范围。用户问题在右侧以气泡呈现；回答在左侧以紧凑、透明的结构化内容呈现，不展示用户或 AI 头像。回答区展示回答、分析思路或信息线索，顶部显示“本次参考 X 个知识库、Y 篇资料”，关键结论附引用标记，并提供有帮助/无帮助反馈。

资料充足且回答存在层级结构时，展示一键生成脑图入口；资料不足时展示已检索到的相关内容、当前缺少的信息及建议补充的资料类型，不输出无依据的完整结论，也不展示生成脑图入口。

## 4.8 来源引用卡片

每条关键结论的句末以论文式 `[1]`、`[2]` 等引用标记关联具体资料；同一结论可关联多条资料。用户 hover 或点击标记后展示来源浮卡，浮卡包含资料标题、所属知识库、来源平台、支持该结论的原文片段及查看原文入口。

## 4.9 笔记与灵感卡片

全局导航提供“首页 / 笔记 / 知识库”。笔记不是任何知识库的从属对象；用户可按需把一篇笔记同步至一个或多个知识库。

| 页面/功能 | 详细需求 |
| --- | --- |
| 我的笔记 | 页头仅「笔记」标题 + 黑色「新建笔记」（与标题底对齐）。左栏工具行：缩小后的笔记本下拉与搜索同一行，其下为按最近编辑分组的列表；右侧富文本工具栏含「已保存」左侧全屏 icon。新建空白笔记进入全屏且不显示素材面板/生成按钮；返回后留在我的笔记并选中该笔记。 |
| 笔记本 | 一篇笔记最多归属一个笔记本。筛选下拉可管理笔记本；删除时弹窗让用户二选一：“仅删除笔记本”（笔记变为未分类）或“连同笔记删除”。 |
| 灵感卡片 | 与「我的笔记」独立；仅用于创作笔记。卡片保存摘录快照、原问题、回答模式与来源上下文。页头去掉筛选；搜索栏延伸至「整理为笔记」前。点击打开详情弹窗。 |
| 收藏入口 | 划选回答文字后显示小浮动工具条；每条回答末尾按 **复制 → 收藏 → 分享 → 更多** 排列。收藏弹出「保存为灵感卡片 / 加入笔记」；分享进入选气泡并替换底栏为「复制对话链接 / 取消」。 |
| 整理为笔记 | 灵感卡片页头固定“整理为笔记”；默认不显示勾选框，点击后进入选择模式。选择条为内嵌圆角长条（约 12px），底色左浅右深弱渐变 `#EEEEED → #E9E9E8 → #E8E8E7`，展示已选数量、取消和开始整理。 |
| 全屏编辑页 | 「新建笔记」→ 全屏无素材面板。「整理为笔记」→ 全屏有底部素材面板。「我的笔记」双栏点全屏 → 若已有灵感素材则显示素材面板。返回均到「我的笔记」并选中该笔记。整理进入时支持拖拽排序、我的想法、添加卡片、生成笔记与自动保存。生成正文的资料型引用为句末内联 `[n]`（不写「（来源：）」）；hover 展开灵感卡片预览菜单，点击打开卡片详情；预览须夹取视口不越界。 |
| 笔记同步知识库 | 一篇笔记可同步到多个知识库，双方正文双向同步。删除某个知识库或其同步资料仅解除关联；删除笔记同时删除其所有同步资料。删除笔记不影响灵感卡片；删除卡片仅移除各笔记素材面板中的卡片，不删除已生成正文。 |

## 4.9 一键生成脑图

入口位于符合条件的 AI 回答底部，由用户主动点击生成。脑图仅基于本轮回答及其已引用资料生成，以问题或回答主题为中心节点，向下展示核心结论、子观点、案例或行动建议。节点支持展开与收起；有来源依据的节点展示引用标记，点击可查看对应来源。脑图生成后自动保存至所属会话，用户再次打开该会话仍可查看；生成失败时提示“脑图生成失败，请重试”。

# 五、核心用户流程

## 5.1 首次使用

`注册（邮箱+密码+用户名）→ 系统自动创建并选中默认知识库 → 进入默认知识库空资料列表 → 点击添加第一篇资料 → 粘贴链接或上传文件 → 资料卡片直接出现并显示解析进度 → 解析完成，展示摘要、标签与来源`

## 5.2 创建知识库

`点击“创建知识库” → 输入名称与简介（选填） → 点击创建 → 创建成功并进入该知识库 → 左侧列表新增并高亮当前知识库 → 右侧展示空资料列表与“添加第一篇资料”引导`

## 5.3 新建资料

`在当前知识库内点击“添加资料” → 选择粘贴链接或上传一个/多个文件 → 系统校验并直接创建资料卡片 → 进度浮窗与列表底部卡片显示上传/解析进度 → 成功后自动生成摘要、标签、索引；失败则保留卡片供重试或删除`

## 5.4 受限平台与其他网页资料导入

`在当前知识库粘贴链接 → 系统识别平台：主流平台（小红书 / 抖音 / 知乎 / B 站 / 公众号）走 MediaCrawler（已连接则用会话，未连接仍可尝试解析或仅保存链接，可引导连接以提升成功率）；其他网页（含搜索结果）匿名抽取正文、不要求用户在目标站注册 → 资料卡片更新为可用，或失败后降级为仅链接`

## 5.5 浏览、搜索与定位资料

`进入首页或知识库详情 → 在搜索框输入自然语言 → 展示搜索建议浮层 → 点击命中资料 → 进入资料详情页或查看原文`

## 5.6 全局 AI 对话

`新建或进入历史对话 → 默认 DS 模型下输入问题并选择联网/不联网 → 可选选择一个或多个知识库、@标签 → 无范围时生成通用任务回答；有范围时强制不联网并按知识库并集、标签 AND 检索 → AI 生成可引用 RAG 回答 → 用户核验来源、继续追问或主动生成脑图`

## 5.7 灵感整理为笔记

`AI 回答中划选片段或点击整答收藏 → 选择保存灵感卡片 → 进入“笔记 > 灵感卡片” → 点击“整理为笔记”并勾选多张卡片 → 开始整理 → 系统创建并打开全屏笔记编辑页 → 调整素材顺序、补充想法 → 点击“生成笔记” → 正文替换为可自由编辑的新结果并自动保存`

# 六、关键业务规则

## 6.1 账户与默认知识库

- V1 支持邮箱与密码注册、登录、忘记密码、退出登录和注销账户；注册时必填用户名；注册后可直接使用，暂不做邮箱验证。
- 注册成功后，系统自动创建一个默认知识库并选中；默认知识库可改名、不可删除，始终作为左侧列表固定知识库；侧栏展示用户真实用户名。
- 每个账户的知识库、资料、对话与平台会话均独立保存并隔离；注销账户需二次确认，确认后永久删除账户及所有关联数据，不可恢复。
- 当前知识库无资料时，显示「当前知识库暂无资料」及添加引导；资料搜索/筛选无命中时显示「未找到符合条件的资料」。
- 侧栏「搜索知识库」无命中时显示「未找到符合条件的知识库」。

## 6.2 知识库创建与管理

- 知识库名称必填，1–30 字；简介选填，最长 100 字；同一用户下不允许创建或改名为同名知识库。
- 列表展示名称、资料数量和最近更新时间；支持编辑知识库名称与简介。
- 删除非默认知识库需二次确认；确认后，知识库及库内全部资料、摘要、标签、资料片段与向量索引永久删除，不可恢复。历史对话保留，但相关引用显示“该资料已删除”。

## 6.3 资料归属规则

- 添加资料始终从当前选中知识库发起，资料固定归属当前知识库；不提供全局添加资料和导入时选择知识库。
- 用户如需保存到其他主题，须先创建并切换知识库；资料保存后可移动至任意知识库，包括默认知识库。

## 6.4 资料上传、解析与直接入库

- 添加资料菜单提供“粘贴链接 / 上传文件”；支持链接、图片、PDF、DOC/DOCX、Markdown、TXT、PPTX、XLSX、CSV，文件支持多选。
- 链接通过合法性校验或文件上传成功后，即创建并保存到当前知识库；资料卡片先显示解析进度，无预览页和人工确认保存步骤。
- 解析成功后生成标题、摘要、标签、主体/节选和检索切片。链接解析正文，图片使用 OCR 与视觉描述，文档和表格提取可读内容。
- 添加资料按钮的白色浮窗按任务显示上传/解析状态；每项在资料列表底部显示“解析中”、圆形进度和百分比，完成后替换为来源平台与标签。
- 同一知识库中重复链接仍提示“该资料已存在”，并提供查看已有资料入口。

## 6.5 内容平台连接与链接解析

- V1 支持小红书、抖音、知乎、B 站、微信公众号的**可选**平台连接；其他网页（含搜索引擎搜到的长尾站）**无需连接、无需在目标站注册**，一律按匿名访客尝试解析正文。
- 当主流平台链接需要登录或访问受限时：已连接则使用该用户的加密平台会话解析；未连接则提示连接可提升成功率，同时提供「仅保存链接」——不得因未连接而拒绝保存链接。
- 用户可在设置页的“连接内容平台”中提前连接，也可在导入时即时连接。登录在 Refind 受控浏览器内由用户自行完成；连接成功后自动继续解析当前链接。
- 每个平台每个用户仅可连接一个账号；断开后可更换账号。断开连接仅停止后续解析，不删除已导入资料。
- 平台会话失效时，提示重新连接并在连接成功后继续当前链接解析；失败资料后续按解析失败规则保留重试/删除与自动降级能力。
- 解析内容仅入库内容主体及基础信息；不入库评论区，不处理视频语音转写。抖音与 B 站：应用内嵌播放（不存视频文件）+ 正文（文案/简介+已有字幕）+ AI 摘要。
- 技术分工：主流平台 → MediaCrawler；其他网页 → Crawl4AI / Readability 类匿名抽取，必要时 Playwright 匿名渲染。

## 6.6 解析失败与降级资料

- URL 合法或附件已上传但解析失败时，保留资料卡片，展示失败原因以及“重新解析 / 删除”。
- 同一资料连续三次解析失败后自动降级为仅链接或仅附件，保留资料归属与原始内容，但正文节选、摘要和标签为空。
- 降级资料支持无限次手动重新解析；成功前不参与搜索、AI 对话或来源引用。

## 6.7 资料列表、关键词搜索与筛选

- 资料以紧凑扁平卡片展示预览图、标题、一行摘要、`#标签`、创建时间与来源平台标签；来源平台标签使用小圆点加平台名称。后台解析成功并自动入库的资料展示新增标记，用户点击资料后标记消失。
- 支持时间（从新到旧/从旧到新）与标题（A–Z/Z–A）排序；默认时间从新到旧，选择排序后列表即时刷新并展示当前排序。
- 支持来源平台单选筛选：全部来源、小红书、抖音、微信、知乎、B 站、其他；筛选菜单以平台小圆点加平台名称展示，可与排序、搜索以 AND 关系同时生效。
- 知识库内搜索为标题、摘要与资料标签的关键词匹配，不使用语义检索；关键词搜索与来源筛选同时命中后，按当前排序规则排列。

## 6.8 搜索建议浮层

- 支持知识库关键词搜索；知识库搜索框用于按名称匹配知识库，资料搜索框仅匹配当前知识库中的标题、摘要与资料标签。
- 输入关键词后展示搜索建议浮层；每条展示标题、所属知识库、匹配片段、标签和来源平台；点击跳转资料详情。
- 输入为空不展示；加载中展示加载状态；无命中展示“未找到相关资料”；点击空白处或关闭按钮关闭。待补充内容资料不参与搜索。

## 6.9 AI 会话与 #标签聚焦提问

- 支持新建、查看、继续、内联重命名和删除历史会话；会话按最近更新时间倒序展示。新建会话立即出现在对应历史列表（草稿标题「新会话」）；首条问题发送成功后自动更新标题。删除会话需二次确认，并永久删除该会话消息、引用与脑图。
- 首页历史与知识库历史分面存储；各知识库会话互不串库。首页选单个知识库提问时，会话归属该知识库历史。
- #标签仅匹配资料标签，不匹配知识库名称；用户可添加一个或多个标签。
- 多个标签为 AND 关系，仅检索同时具备全部标签的资料；未添加时默认检索全部知识库。
- 标签不存在或范围内无相关资料时提示当前范围无相关资料；资料不足时不得自动扩大检索范围。

## 6.10 AI 对话与来源溯源

- AI 对话从首页工作台右栏发起。默认 DS（DeepSeek）模型；未选择知识库或 @标签时为普通任务对话，用户可主动选择联网或不联网，且不展示资料引用。
- 只要选择一个或多个知识库、或任意 @标签，即切换为严格 RAG：系统强制关闭联网，只从 `ready` 的用户资料和当前会话检索。多个知识库取并集，多个标签按 AND 关系筛选；仅选标签时在用户全部知识库范围内筛选。
- 用户选定的模型、联网状态、知识库与标签范围在当前会话持续有效，直到用户手动变更或新建会话。严格 RAG 每轮重新检索，回答顶部展示参考知识库数量与资料数量。
- 用户问题以右侧气泡呈现；AI 回答以左侧无卡片容器、紧凑的结构化文本呈现，不展示对话头像。
- 关键结论、观点和案例须在句末附论文式来源引用；hover 或点击引用展示资料标题、所属知识库、来源平台、支持结论的原文片段及查看原文入口。
- AI 可归纳多篇资料，但不得将推断表述为既有事实；资料明显冲突时需说明差异并分别标注来源。

## 6.11 笔记、灵感卡片与同步

- 笔记正文使用所见即所得富文本编辑，用户无需认识或输入 Markdown；任意输入、格式调整、AI 写入或素材调整后 1–2 秒自动保存，离开和生成前后立即保存，并提供撤销/重做。
- 灵感卡片保存的是独立快照。片段收藏只保存选中文字；整答收藏保存整条回答。原会话或资料后续删除不影响卡片正文可读性；不可用来源应被标识。
- 通用 AI 卡片标记回答模式，不伪造资料引用；严格 RAG 卡片保存引用快照，生成笔记时自动写入可交互内联 `[n]`（绑定灵感卡片；hover 预览、点击打开卡片详情；预览不超出屏幕）。
- 从空白「新建笔记」进入的全屏页不显示素材面板或生成按钮；从「整理为笔记」进入的全屏页显示素材面板和「生成笔记」。双栏点全屏时，若笔记已有灵感素材则显示素材面板。灵感卡片选择态使用内嵌圆角选择条与左浅右深弱渐变底色。
- 笔记可同步至多个知识库，同步采用非阻塞反馈。笔记与同步资料同一正文双向更新；删除笔记同时永久删除全部同步资料，删除知识库或其中同步资料只解除关联。
- 用户可继续追问，后续回答仍基于知识库资料与当前对话上下文。

## 6.11 一键生成脑图

- 用户主动点击某条 AI 回答底部的“生成脑图”后触发；仅当回答资料充足且存在可组织层级时展示入口。
- 脑图仅基于该回答及已引用资料生成，包含中心主题、核心结论、子观点、案例或行动建议；有来源依据的节点提供引用标记。
- 脑图生成成功后保存至当前会话，打开历史会话仍可查看；失败时仅提示重试，不影响原回答。

## 6.12 资料不足处理

以下情况触发资料不足：未检索到相关资料、资料相关性较弱、资料仅覆盖部分问题，或存在无法判断的冲突。此时 AI 不输出看似完整但无依据的结论，应说明已找到的内容、缺少的信息及建议补充的资料类型。

# 七、AI 能力方案与验收标准

## 7.1 AI 技术方案

Refind V1 采用 RAG（检索增强生成）架构。AI 不直接基于通用知识回答，而是先从知识库中检索相关资料，再基于检索结果生成回答，并为关键结论提供来源引用。

```text
用户保存链接 → 解析网页内容 → DeepSeek 生成摘要与标签 → 正文切分为资料片段 → Embedding 向量化 → pgvector 建立索引
用户提问 → 解析 #标签 → 问题向量化 → 标签过滤 → pgvector 相似度检索 → DeepSeek 基于片段回答 → 绑定来源引用
```

## 7.2 模型与技术组件分工

| 组件 | 技术选型 | 主要职责 |
| --- | --- | --- |
| 生成模型 | DeepSeek Chat | 生成资料摘要、标签，以及基于检索片段生成最终回答。 |
| 向量模型 | 阿里云百炼 text-embedding-v4 | 将资料片段与用户问题转换为向量，用于中文语义检索。 |
| 向量存储与检索 | Supabase Postgres + pgvector | 存储向量，按相似度检索相关资料片段，并结合标签过滤。 |
| 关系数据存储 | Supabase Postgres | 保存知识库、资料、标签、资料片段、引用关系与对话记录。 |
| 受限平台解析 | MediaCrawler + 平台解析适配器 | 使用当前 Refind 用户**可选**已连接的平台会话，解析小红书、抖音、知乎、B 站和微信公众号链接的内容主体。 |
| 其他网页解析 | Crawl4AI / Readability 类；必要时 Playwright 匿名渲染 | 匿名抽取标题与正文；不要求用户在目标站注册。 |
| 后端编排 | Supabase Edge Functions | 串联平台会话、链接解析、结构化、向量化、检索、回答生成与引用返回。 |

## 7.3 资料入库与索引构建

1. 解析链接，获取标题、作者、发布时间、来源平台、正文或内容节选；主流受限平台按需使用用户已连接的平台会话；其他网页匿名抽取。
2. 调用 DeepSeek Chat 生成资料摘要与标签。
3. 对正文清洗并按段落或固定长度切分为多个资料片段。
4. 调用 text-embedding-v4 为每个资料片段生成向量。
5. 将资料片段、向量及资料 ID、知识库 ID、标题、平台、URL、标签和原文位置等元数据保存至 pgvector。

资料编辑、移动、重新解析或删除后，需同步更新或删除相关资料片段与向量，避免过期内容参与检索。待补充内容资料不生成向量；**评论区与视频语音转写**不在 V1 入库范围内。图片 OCR、抖音/B 站文案与已有字幕属于 V1 正文；视频资料同样生成 AI 摘要与检索切片。播放采用应用内嵌，不托管视频文件。

## 7.4 提问理解与检索规则

系统将用户问题转换为向量，在可用资料片段中召回语义最相关内容。含 #标签时，先按资料标签过滤，再执行向量相似度检索；多个标签采用 AND 关系，范围内资料不足时不扩大范围。不含 #标签时，在全部知识库可用资料片段中检索，并保留所属知识库信息用于回答展示。

## 7.5 回答生成规则

- 仅使用检索到的资料片段与当前对话上下文；不联网，不使用知识库外信息补充。
- 优先直接回应用户问题，可归纳多篇资料中的共同观点、案例或差异。
- 对未直接说明的推断，使用“根据现有资料可推断”“可进一步考虑”等表达。
- 对资料间明显冲突说明差异，不强行给唯一结论。
- 每个关键事实、案例、观点或结论必须关联至少一条来源；不得将资料中不存在的内容描述为既有事实。

## 7.6 来源引用与溯源

- 关键结论后展示引用标记，如 [1]、[2]；同一结论可关联多条来源。
- 点击引用打开来源卡片，展示资料标题、所属知识库、来源平台、支持结论的原文片段和查看原文入口。
- 回答顶部展示“本次参考 X 个知识库、Y 篇资料”，用户可展开查看本轮使用的全部资料。

## 7.7 资料不足判断

未检索到相关资料、召回资料相关性低、资料只覆盖问题的一部分、资料内容过短或存在无法判断的冲突时，AI 应优先说明边界。回复需包含已找到的相关内容、现有资料无法覆盖的部分及建议补充的资料类型。

## 7.8 AI 验收标准

| 能力 | 验收标准 |
| --- | --- |
| 摘要生成 | 能概括资料核心信息；用户可编辑；生成失败不阻断资料保存。 |
| 标签生成 | 标签反映资料主题；可用于 #标签 过滤；用户可编辑。 |
| 语义检索 | 输入自然语言后，可召回标题不完全匹配但主题相关的资料。 |
| 标签聚焦 | 使用多个 #标签 时，仅检索同时具备全部标签的资料。 |
| 知识库问答 | 回答仅使用检索到的知识库资料，不出现知识库外事实性补充。 |
| 来源引用 | 每个关键结论至少有一个可打开来源；来源片段能支持该结论。 |
| 资料不足 | 无相关或依据不足时明确提示资料不足，不生成无来源的完整结论。 |
| 数据边界 | 待补充、已删除或不可用资料不得被检索或引用。 |

# 八、数据指标与迭代规划

## 8.1 指标设计目标

V1 数据指标用于评估 Refind 是否帮助用户完成“资料沉淀、知识找回、AI 调用与来源核验”的核心使用链路，并识别资料解析、检索与回答中的主要问题。

`创建知识库 → 添加资料 → 搜索或提问 → 获得回答/资料 → 查看来源 → 继续使用`

## 8.2 核心指标

| 模块 | 指标 | 定义 | 观察目的 |
| --- | --- | --- | --- |
| 知识库创建 | 知识库创建完成率 | 成功创建次数 ÷ 点击创建次数 | 判断创建流程是否顺畅。 |
| 资料沉淀 | 资料入库完成率 | 成功进入 `ready` 的资料数 ÷ 发起上传/解析资料数 | 判断直接入库与解析流程是否顺畅。 |
| 资料沉淀 | 解析成功率 | 成功获得标题或正文节选资料数 ÷ 发起解析资料数 | 判断链接解析能力。 |
| AI 结构化 | 摘要编辑率 | 被用户修改摘要数 ÷ AI 生成摘要数 | 判断摘要是否符合用户理解。 |
| AI 结构化 | 标签编辑率 | 被新增、删除或修改标签数 ÷ AI 生成标签数 | 判断标签质量及可用性。 |
| 资料找回 | 搜索结果点击率 | 点击搜索建议条目次数 ÷ 浮层展示次数 | 判断检索结果相关性。 |
| AI 调用 | AI 对话发起率 | 至少发起一次对话用户数 ÷ 拥有至少 3 篇可用资料用户数 | 判断用户是否认可向资料库提问。 |
| AI 调用 | 有效知识问答完成数 | 含来源回答后，用户点击来源、继续追问、复制回答或查看原文的次数 | 衡量回答是否被实际使用。 |
| 可信度 | 引用点击率 | 点击任一来源引用回答数 ÷ 含引用回答数 | 判断溯源是否建立信任。 |
| 资料不足 | 资料不足率 | 返回资料不足回答数 ÷ AI 回答总数 | 判断资料覆盖度与检索效果。 |
| 留存 | 7 日回访率 | 首次访问后 7 日内再次访问用户数 ÷ 首次访问用户数 | 判断持续使用价值。 |

## 9.1 信息架构澄清

- **首页** 与 **知识库** 是并列一级导航，不是「登录后首页即三栏知识库工作台」。
- **首页**：欢迎区 + 全局 AI 输入；可进行通用任务对话，或在选择知识库 / `#标签` 后进行严格 RAG。
- **知识库**：中部资料列表 + 右侧当前库 AI 对话。
- 首页 AI 会话与知识库 AI 会话 **相互独立**；首页发送问题 **不得跳转** 到知识库 AI 面板。

## 9.2 首页对话交互（已落地）

- 用户在首页发送后，欢迎区收起，同页展开对话流；底部保留输入框继续追问。
- 用户问题右对齐气泡，回答左对齐结构化文本；样式按首页对话流单独设计。
- 品牌「拾藏」回到欢迎区并保留最近会话；导航「首页」在已有会话时恢复对话；「新增会话」清空气泡但留在对话表面。
- 对话出现后展示可折叠的左侧历史会话浮动卡片；折叠后对话区居中，展开后与输入框共宽左对齐。
- 范围、联网与严格 RAG 规则不变：无范围默认可不联网；有知识库或标签则强制不联网并仅基于资料回答。
